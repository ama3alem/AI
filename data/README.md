# Data directory

```
data/
├── raw/         # captured event streams — currently EMPTY
├── processed/   # derived feature frames — currently EMPTY
└── synthetic/   # simulator output — currently EMPTY
```

All three directories are empty. Nothing has been generated yet; the simulator arrives in
Phase 4.

Contents are git-ignored (`.gitkeep` files only are tracked). This is deliberate: data is
regenerable from a recorded seed, and the working directory may sit on a synchronised
folder where a sync conflict could corrupt a generated artifact. See `PROJECT_AUDIT.md`
risk R-03.

---

## ⚠ SYNTHETIC DATA — NOT REAL STUDENT DATA

**No real learner data exists in this repository.**

Any file that appears under `data/synthetic/` is generated by the synthetic learner
simulator from its own generative parameters. Such data:

- does **not** describe any real person;
- must not be presented as evidence that this system works on real students;
- validates **software and architecture only** — that the pipeline runs, that features are
  deterministic, that baselines mature correctly, that leakage tests detect leakage.

Generated datasets will additionally carry an in-band `SyntheticDataStamp`
(`SYNTHETIC DATA — NOT REAL STUDENT DATA`) inside the data itself, so a file remains
self-identifying after it is copied, concatenated, or loaded by a tool that never read
this README.

---

## `raw/`

Intended for append-only captured event streams, in the validated event schema. A file
placed here by hand is a defect unless it was produced by a documented ingestion path and
carries its provenance stamp.

## `processed/`

Intended for derived feature frames, each labelled with the `FEATURE_SET_V*` version
under which it was computed. A processed frame without a feature-set version is
uninterpretable and must not be written.

## `synthetic/`

Intended for simulator output, each accompanied by the generator version and the seed
used, sufficient to regenerate it byte-identically.

---

## Handling rules

- Pseudonymous identifiers only. No name, email, precise location, device fingerprint, or
  unrelated browsing data — see `PRIVACY.md`.
- Every artifact carries provenance: dataset version, feature-set version, and content
  digest.
- No artifact is the sole copy of anything. Anything here is reproducible from a seed or
  a source stream.
